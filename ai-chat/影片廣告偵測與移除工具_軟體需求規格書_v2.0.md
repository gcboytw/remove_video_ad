# 影片廣告偵測與移除工具
## 軟體需求規格書（SRS）— 第二版 v2.0

- **專案名稱：** Video Ad Detector & Remover
- **開發語言：** Python
- **核心工具：** FFmpeg / FFprobe
- **目標平台：** macOS、Windows
- **介面方向：** 桌面 GUI，建議使用 PySide6
- **處理原則：** 先找出候選廣告，再由使用者確認，最後剪輯輸出
- **版本：** 2.0

---

## 文件目的

本文件作為後續軟體設計、開發、測試與驗收的依據。

## 1. 專案背景與目標

### 1.1 背景

影片會在正片播放途中插入全畫面廣告卡，廣告持續約 **25 秒**，結束後直接恢復正片。同一部影片通常出現 **2～3 次**，出現位置不固定。廣告畫面具有圖卡、醒目文字／字幕及裝飾圖像，但不假設所有廣告都具有完全相同的顏色或版面。

### 1.2 核心目標

1. 掃描整部影片，找出所有疑似廣告的開始與結束切換點，不因找到第一段廣告而停止。
2. 以「**場景切換偵測＋片段持續性分析**」為第一版主要偵測策略。
3. 將約 25 秒作為廣告時長線索，而非固定剪除時長。
4. 提供影格級定位及人工確認，允許精確修改起訖點。
5. 依確認結果移除多段廣告，將正片合併並輸出 MP4。
6. 優先確保剪輯正確、正片內容保留、音畫同步；必要時重新編碼。
7. 完全在本機處理，不上傳影片。

### 1.3 非目標

- 第一版不承諾完全無人介入的廣告辨識。
- 不以單一顏色、字幕存在與否或固定 25 秒長度作為唯一判斷依據。
- 不提供一般影片製作所需的特效、調色、多軌剪輯等功能。
- 不修改或刪除原始影片。

## 2. 使用情境與主要流程

1. 使用者載入影片，程式以 FFprobe 取得影片與音訊串流資訊。
2. 程式掃描整部影片，偵測場景切換候選點。
3. 程式分析切換點前後的畫面差異與候選片段持續時間，找出疑似廣告區間。
4. 程式將所有候選區間整理成清單，並提供開始前、廣告開始、廣告結束前、正片恢復後的影格預覽。
5. 使用者逐格確認或修改每段廣告的起訖影格，也可新增、刪除或合併區間。
6. 程式產生待刪除區間與保留區間清單，供使用者確認。
7. FFmpeg 執行剪輯與必要的重新編碼，輸出 MP4。
8. 程式檢查輸出檔案、影音串流、預期長度與剪輯邊界，並保存專案資料。

## 3. 系統架構

| 模組 | 責任 |
|---|---|
| 影片資訊 | 讀取解析度、影格率、時長、編碼、音訊資訊、影格時間戳記等。 |
| 場景切換偵測 | 快速掃描影片並產生疑似畫面切換點。 |
| 廣告候選分析 | 以切換點、候選片段長度、視覺差異及片段內部特徵排序候選廣告。 |
| 人工確認介面 | 顯示候選清單、影格預覽、逐格移動及起訖點編輯。 |
| 剪輯輸出 | 依確認後的區間剪除廣告、合併保留片段並輸出 MP4。 |
| 驗證與專案管理 | 檢查輸出、保存 JSON 專案、處理錯誤及中斷恢復。 |

## 4. 功能需求

### FR-001：影片載入

- 支援常見容器格式，例如 MP4、MOV、MKV、M4V；實際支援度依 FFmpeg 與來源編碼而定。
- 載入後顯示檔名、檔案大小、時長、解析度、影格率及影音編碼。
- 原始檔案只讀，不得被修改。

### FR-002：影格級定位

- 提供前一格、下一格、指定影格數跳轉及指定時間跳轉。
- 顯示目前影格索引與時間戳記。
- 固定影格率影片以解碼影格建立一致索引；可變影格率（VFR）影片以實際影格時間戳記定位。
- 不得只用播放器顯示的四捨五入秒數推算影格位置。

### FR-003：全片場景切換掃描

- 每次分析必須掃描整部影片，不能找到第一段候選廣告後就停止。
- 初步分析可採低解析度影格取樣，預設每秒約 2～5 個樣本；取樣率應可調整。
- 使用場景切換偵測、影像直方圖差異、亮度／色彩變化等方法產生候選切點。
- 候選點不是廣告的確定證據；正片自身場景切換也必須允許出現在清單中。

### FR-004：廣告片段持續性分析

- 以約 25 秒作為預期廣告時長的先驗線索，而非固定剪除長度。
- 初始候選持續時間範圍建議為 **15～35 秒**，且必須可調整或關閉。
- 檢查候選開始點之後的畫面是否呈現一段不同於前後正片的視覺狀態，並尋找恢復正片的切換點。
- 可評估片段內部版面／色彩分布的穩定程度，但不得要求廣告每一格都相同。
- 候選區間可因轉場、片頭或片尾而偏離 25 秒；起訖點必須依影格證據及人工確認決定。

### FR-005：候選區間評分與排序

- 綜合開始／結束切換強度、候選時長、片段內部視覺特徵與前後畫面差異，為候選區間排序。
- 分數僅代表檢查優先級，不可直接解讀為廣告判定的機率或準確率。
- 對重疊或高度相近的候選區間進行去重或合併，並保留人工調整能力。

### FR-006：候選清單與預覽

- 每個候選至少顯示候選編號、起訖時間、起訖影格索引、持續時間、評分／排序依據及確認狀態。
- 提供四個關鍵預覽：廣告前一格、廣告第一格、廣告最後一格、正片恢復第一格。
- 使用者選取候選項目時，預覽位置跳至相應影格。
- 可以依時間排序，並標示尚未確認、已確認為廣告、已排除等狀態。

### FR-007：手動編輯廣告區間

- 使用者可新增、修改、刪除、合併及拆分廣告區間。
- 可逐格微調起始與結束邊界，並即時預覽邊界影格。
- 檢查起訖順序、空區間及重疊區間；必要時提示使用者處理。
- 未經使用者確認，不得直接刪除候選片段。

### FR-008：剪輯清單與預覽

- 將確認的廣告區間轉換為正片保留區間。
- 輸出前顯示將刪除的區間、保留片段及預估輸出時長。
- 允許使用者逐一預覽各個接合點，尤其是正片恢復位置。

### FR-009：MP4 輸出

- 預設輸出 MP4，建議使用 H.264 影片與 AAC 音訊以提高相容性。
- 預設保留來源解析度及影格率特性；不得未經提示就把 VFR 強制轉成 CFR。
- 輸出路徑預設為原始檔名加上 `_ad_removed.mp4`。
- 可設定品質、編碼器及輸出位置；來源編碼與輸出設定不相容時須顯示提示。
- 如需任意影格精確剪輯，允許重新編碼；無損剪輯不得凌駕於正確剪輯邊界之上。

### FR-010：音訊與時間戳記

- 影音應以一致的時間區間同步裁切，並處理音訊編碼延遲、時間戳記及片段合併問題。
- 剪輯邊界以影片影格為主要依據；音訊依對應時間區間處理。
- 輸出後應檢查是否有明顯影音不同步、音訊缺失或不合理的時間戳記。

### FR-011：專案儲存與恢復

- 以 JSON 儲存來源檔案路徑、來源資訊、候選點、確認後區間、輸出設定及修改時間。
- 重新開啟專案時，若來源檔案位置變動，應提示使用者重新定位來源檔案。
- 專案資料不得包含整部影片的副本。

### FR-012：進度與錯誤處理

- 顯示掃描／細部分析／輸出階段、進度與可取得的剩餘時間估計。
- 提供取消操作；取消後不得影響原始影片。
- 輸出中斷時清楚標示未完成檔案，並安全處理暫存資料。
- 顯示 FFmpeg 錯誤摘要及必要的診斷資訊。

### FR-013：輸出驗證

- 確認輸出檔案存在且 FFprobe 可讀取。
- 確認預期影音串流存在，並檢查輸出時長是否接近保留片段時長總和。
- 對測試素材可逐格比對保留區間與輸出內容，確認沒有誤刪或重複影格。
- 輸出驗證失敗時保留來源檔案與專案，並告知使用者。

## 5. 偵測流程與演算法原則

### 5.1 第一階段：快速全片掃描

以低解析度、可調整的取樣頻率掃描全片，偵測明顯場景切換。建議初始取樣頻率為每秒 2～5 格，分析解析度長邊約 320～480 像素。此數值是初始設定，不是精度保證。

### 5.2 第二階段：候選片段分析

針對場景切換點前後的時間範圍，尋找開始切換與恢復正片的可能邊界。以約 25 秒為中心、初始 15～35 秒的可調範圍評估候選片段，並檢查片段內的視覺特徵是否與前後正片有持續差異。

### 5.3 第三階段：邊界精確化

候選區間確立後，只對候選開始與結束附近進行逐格解碼／檢查，將粗略時間定位細化為影格索引與時間戳記。快速掃描的取樣影格只用於發現候選，不可直接當作最終剪輯邊界。

### 5.4 偵測限制

- 全畫面廣告通常會造成明顯場景切換，適合以場景切換偵測作為第一層線索。
- 廣告內部可能包含動態動畫、字幕或多次快速切換，因此不應要求廣告期間每一格都相似。
- 正片可能有約 25 秒的場景段落，故持續時間不能單獨作為廣告證據。
- 若廣告與正片的視覺差異不明顯，系統應降低信心或列為待人工確認，而不是自動刪除。
- 第一版不保證完全自動辨識；成功標準是有效縮小人工搜尋範圍並提供可靠的精確剪輯流程。

## 6. 影格區間與剪輯精度

### 6.1 區間定義

統一使用半開區間 `[start_frame, end_frame)` 表示欲刪除的影格。例如 `[1000, 1500)` 代表刪除影格索引 1000 至 1499，保留索引 1500。介面必須明確標示索引從 0 或 1 開始，內部資料格式全程使用同一規則。

### 6.2 固定／可變影格率

固定影格率（CFR）影片應以實際解碼影格建立索引，並記錄來源影格率。可變影格率（VFR）影片應使用實際影格時間戳記；不得只用 `frame_index / nominal_fps` 推算精確時間。

### 6.3 無損剪輯限制

H.264／H.265 等編碼可能依賴關鍵影格。直接複製壓縮資料未必能在任意影格精確切割。因此第一版以正確的剪輯邊界為最高優先，必要時採用重新編碼。若未來提供無損模式，必須提示其切點可能受關鍵影格限制，並讓使用者選擇精確度或無損優先。

## 9. 非功能需求

- **跨平台：** 核心邏輯應避免綁定單一作業系統路徑或 shell 語法。
- **可用性：** 主要操作可透過 GUI 完成，不要求使用者手動撰寫 FFmpeg 命令。
- **可恢復性：** 分析或輸出失敗不得損壞來源檔案；剪輯區間可保存後繼續。
- **可追溯性：** 每個候選點的來源、分數及人工確認結果均應可查看。
- **效能：** 快速掃描與候選區域細部分析分離，避免一開始就逐格解碼整部長片。
- **隱私：** 不需要網路服務，不上傳影片。
- **安全：** 預設不覆寫來源檔；輸出檔同名時先詢問。

## 11. 開發階段與交付成果

### Phase 1：剪輯核心與人工確認

- 讀取影片資訊、建立影格索引。
- 逐格預覽與手動標記廣告區間。
- 依半開區間產生剪輯清單。
- 使用 FFmpeg 輸出 MP4，並驗證剪輯邊界與影音同步。

### Phase 2：全片自動候選偵測

- 整部影片場景切換掃描。
- 約 25 秒時長線索與持續性分析。
- 候選評分、排序、去重與四張邊界影格預覽。
- 人工確認後一鍵輸出。

### Phase 3：偵測品質改善（選配）

- 加入音訊變化分析或其他輔助特徵。
- 支援使用者提供廣告參考影格。
- 依實際測試影片調整候選時長、取樣頻率及評分規則。
- 評估批次處理與進階辨識能力。

### 交付項目

1. Python 原始碼與依賴套件清單。
2. FFmpeg／FFprobe 安裝與使用說明。
3. 操作手冊及已知限制。
4. 合成測試影片或可重現的測試素材與驗收流程。
5. JSON 專案格式說明。
6. 測試結果與已知問題清單。
