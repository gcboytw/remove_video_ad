# Stage 2 候選區間配對效能優化實施計畫

---

## 1. 背景與核心原則

### 1.1 現行 Stage 2 機制與角色定位
* **粗略候選定位**：Stage 2 的職責是從 Stage 1 產生的切點（Cutpoints）中，篩選出合理的廣告「粗略候選區間」；最終的精確邊界由 Stage 3 進行局部逐格時間校正。
* **時長窗約束**：現行配對時長窗設定為 **18–32 秒**，切點已按時間排序，因此在內層迴圈超出 32 秒上限時即會 `break`。實際運算複雜度為 $O(N \cdot K)$（$K$ 為落在時間窗內的候選數），而非全片切點的完全 $O(N^2)$。
* **影格取樣模式**：現行邏輯針對每個組合，會透過 `get_frame()` 進行隨機 seek，依序讀取 **2 張 context 影格**（起點前、終點後）與 **4 張內部樣本影格**（20%、40%、60%、80% 處）。注意內部比較是計算相鄰影格差異，4 張內部樣本會產生 **3 次相鄰差異比較（`expected_diffs = 3`）**。

### 1.2 現行效能瓶頸
1. **無快取重複隨機 Seek**：`get_frame()` 為非關鍵影格隨機跳轉，解碼器需回溯 GOP 前方的 I-frame 並逐格解碼至目標影格，耗時達數十至數百毫秒。
2. **Context 影格反覆解碼**：同一個切點作為起點或終點，會與多個候選重複配對，導致邊界影格重複解碼多次。
3. **等比例縮圖失真**：現行 `target_size=(160, 90)` 對非 16:9 影片造成強制拉伸，影響特徵萃取穩定度。
4. **無效運算未受阻絕**：缺少便宜的純數值前置過濾，且內部抽樣在已註定超標的情況下依然全數解碼完成。

### 1.3 核心實施原則
* **防禦性工程**：絕不以犧牲召回率（Recall）為代價換取效能；不盲目假設「加速比必達數倍」或「準確率完全不變」。
* **變更隔離與分階驗收**：嚴格將「純效能優化（零行為變更）」與「模型/特徵/決策變更」拆分至不同階段驗收，杜絕混合改動帶來的歸因困難。
* **數據驅動與參數化**：所有過濾與早停機制必須參數化，並透過 Shadow Mode（觀察模式）收集數據後再正式啟用。
* **嚴謹數學安全早停**：僅在數學邏輯上保證必定超標時提前中止，避免單一噪點、字幕或局部動畫造成誤殺。

## 2. 實施步驟詳解

```
[Step 1] 建立 Profiling 基準與真值回歸環境
   ↓
[Step 2] 實作函式層級特徵快取 (LRU/容量上限) 【零行為變更】
   ↓
[Step 3] 等比例縮圖導入與特徵分數校準 【特徵變更・獨立驗收】
   ↓
[Step 4] 健全例外處理機制 (解碼失敗策略) 【決策變更・獨立驗收】
   ↓
[Step 5] 數值先驗預篩 (Cheap Math Pre-filter) 導入 Shadow Mode
   ↓
[Step 6] 實作數學安全型「不可逆超標」早停機制 (3 次相鄰比較) 【零行為變更】
   ↓
[Step 7] (視瓶頸評估) 短距分群連續解碼 (Grouped Sequential Decoding)
```

---

### Step 1：建立 Profiling 基準與真值回歸環境

#### 1.1 目標
在修改任何演算法與快取前，建立精確的效能與準確率基準線（Baseline），作為後續每一次改動的對照依據。

#### 1.2 具體實作
1. **耗時指標採集**：在 Stage 2 函式內部加入細粒度計時與計數器：
   * 總候選配對數（Total Candidate Pairs）
   * 實際執行解碼的次數（Total `get_frame()` Calls）
   * 影格解碼累計耗時 vs 特徵計算累計耗時
   * 平均每個影片處理 Stage 2 的總 Wall-clock Time
2. **真值回歸測試集**：
   * 選定代表性測試影片（包含標準 16:9、不同解析度、以及含弱切點廣告的測試檔）。
   * 固化目前的輸出結果（候選區間清單、各項配對分數），建立回歸驗證腳本。

---

### Step 2：實作函式層級特徵快取池（LRU / 容量上限）

> **[驗收特性]** 純效能優化，此階段**不包含縮圖尺寸變更**，候選區間與分數必須與 Baseline **100% 完全一致**。

#### 2.1 快取設計要點
* **生命週期**：快取池生命週期限定在單次呼叫的函式區域（Function Scope），函式結束即釋放，避免跨任務記憶體洩漏。
* **容量上限與淘汰策略**：在高切點密度長片中，內部 20/40/60/80% 影格雖然不易跨區間重複，但仍會累積大量 Unique Index。快取應引入最大容量限制（例如 `maxsize=1024` 的 LRU 機制），防止記憶體過度膨脹。
* **Key 定義**：以 `frame_index` 為鍵值，Value 為 `tuple[np.ndarray, np.ndarray] | None`（含影像特徵向量與色方圖/邊緣特徵）。
* **效益範圍**：
  * **起迄切點 Context 影格**：高度重複，命中率極高，可大幅降低 Seek 次數。
  * **內部 4 格取樣**：作為短暫生命週期的備查，若有相鄰候選剛好取到同格亦可受益。

---

### Step 3：等比例縮圖導入與特徵分數校準

> **[驗收特性]** 特徵模型變更，分數會發生合理變動。**不驗收 score 完全一致**，改為驗收「真值召回率（Recall）不得下降、誤判率（Precision）穩定、候選排序合理」。

#### 3.1 實作要點
* 原程式採用 `cv2.resize(img, (160, 90))` 會將 4:3、直式或非 16:9 影片強制拉伸變形，導致邊緣偵測與直方圖分佈失真。
* 改為**等比例縮放（Aspect Ratio Preservation）**：
  * 維持長邊縮放並輔以 Letterbox 填黑邊，或等比例縮小長寬比。
* **獨立驗證**：在測試集上重新比對特徵評分分佈，確認改動後的特徵更具物理代表性，且真值廣告的排序未受不利影響。

---

### Step 4：健全例外處理機制（精確定義解碼失敗）

> **[驗收特性]** 決策邏輯微調，獨立於快取驗收之外。

#### 4.1 失敗定義與正常畫面區分
* **不得將「全黑 / 全白」直接視為 `INVALID_SAMPLE`**：
  * 真實廣告（尤其是電視廣播與片頭廣告）常包含黑場過場、淡入淡出或純白圖卡。全黑/全白是正常的影像內容，不得粗暴視為解碼錯誤，僅能作為可選的診斷訊號記錄。
* **嚴格定義解碼失敗**：
  * 僅在 `get_frame()` 回傳 `None`、影像維度不合法（如 `img.size == 0`）、或 OpenCV 解碼底層拋出異常時，才標記為真正的解碼失敗。

#### 4.2 樣本不足策略定義
* 現行內部抽樣為 4 格（產生 3 次比較）。若遭遇解碼失敗導致有效樣本數少於 3 格：
  * **明確策略**：不得因無法計算差異而誤判為「極度穩定」，應對該區間進行降分（Penalty）或在有效樣本極少時標記為不可信，此變更需單獨驗證召回影響。

---

### Step 5：數值先驗預篩與 Shadow Mode 收集

#### 5.1 參數化設計 (`PairConfig`)
所有門檻一律外置於組態，禁止寫死於程式碼：
* `min_boundary_diff_score`：起迄點最小轉場強度（預設關閉或設為極低，保護弱切點廣告）。
* `min_pair_duration`：最小廣告長度（預設 18.0s）。
* `max_pair_duration`：最大廣告長度（預設 32.0s）。

#### 5.2 Shadow Mode 驗證流程
1. **第一階段（只記 log 不淘汰）**：
   * 候選組合若未達預篩門檻，僅在 log 標記 `[Shadow Pre-filter Reject]`，仍繼續執行解碼與完整判定。
   * 比對被標記淘汰的組合中，是否有任何真值廣告被誤傷。
2. **第二階段（門檻校準後啟用）**：
   * 收集足夠樣本並確認真值召回率 100% 保持後，才正式改為提早 `continue`。

### Step 6：數學安全型「不可逆超標」早停機制

> **[驗收特性]** 純效能優化，在數學上保證最終決策 100% 與跑完全程完全相同。

#### 6.1 嚴謹數學式修正（3 次相鄰比較）
內部共抽樣 4 張影格，計算的是相鄰影格差異，因此**總比較次數只有 3 次**：
$$N_{\text{diffs}} = 3 \quad (\text{Sample 0 vs 1, 1 vs 2, 2 vs 3})$$

* 門檻上限：$S_{\text{limit}} = \text{cfg.max\_internal\_variance} \times 3$。
* 設已累積的前 $k$ 次相鄰差異總和為 $S_{\text{accumulated}}$（$k \in \{1, 2\}$）。
* 剩餘未測之差異次數為 $3 - k$。
* **安全早停條件**：
  $$\text{若 } S_{\text{accumulated}} + 0 \times (3 - k) > S_{\text{limit}} \implies \text{立即 break}$$
  也就是直接判斷：
  ```python
  expected_diffs = 3  # 4 samples -> 3 adjacent comparisons
  sum_limit = cfg.max_internal_variance * expected_diffs

  if accumulated_diff > sum_limit:
      break
  ```
* **數學安全保證**：即便後續所有未檢查的相鄰差異全數為 0，整體平均方差依然必定超標。此判定與完整跑完 3 次比較的最終布林結果**完全一致**，達成零召回率損失（Zero False Negative）。

---

### Step 7：（進階擴展）短距分群連續解碼（Grouped Sequential Decoding）

#### 7.1 觸發條件
若執行完 Step 1–6 後，隨機 Seek 依然是主要 I/O 瓶頸，才評估啟用此機制。

#### 7.2 分群解碼原則（避免全片無差別重串流）
* 不可為了全片零散分佈的少數影格把整支影片全域串流重解一次。
* **分群策略**：
  1. 收集所有候選組合所需的目標 `frame_indices`，去重並依時間軸升冪排序。
  2. 計算相鄰目標影格間的距離 $\Delta F = F_{i+1} - F_i$。
  3. **動態分群**：
     * 若 $\Delta F \le \text{Threshold}$（例如 $\le 30 \sim 60$ 幀 / 一個 GOP 內），視為同一個連續解碼群組，使用循序前向讀取。
     * 若 $\Delta F > \text{Threshold}$，斷開群組，下一群組重新進行專門 Seek。
  4. 解出的影格依序灌入 Step 2 的快取池，供後續候選評估直接命中。

## 3. 驗收標準與驗收指標（拆分驗收體系）

為了避免行為變更與效能優化相互干擾，驗收標準嚴格區分為兩大類：

### 類別 A：純效能優化驗收（Step 2 快取、Step 6 純安全早停）
| 驗收項目 | 指標門檻 | 驗證方式 |
| :--- | :--- | :--- |
| **候選名單與分數** | **Byte-for-byte 100% 完全一致** | 比對改動前後輸出的候選區間與各項評分 diff 必須為空 |
| **I/O 呼叫降幅** | `get_frame()` 呼叫次數顯著下降 | Profiling 計數器對比 |
| **真值召回率** | **零回退（Zero Regression）** | 既有 Ground Truth 廣告檢出率 100% 保持 |

### 類別 B：特徵與決策變更驗收（Step 3 等比例縮圖、Step 4 預篩、Step 5 例外策略）
| 驗收項目 | 指標門檻 | 驗證方式 |
| :--- | :--- | :--- |
| **真值召回率** | **不得低於 Baseline** | Ground Truth 測試集回歸，不允許漏抓既有已知廣告 |
| **誤判率 (FP)** | 等於或優於 Baseline | 檢視假陽性區間數量是否減少或持平 |
| **候選排名穩定度** | 正確廣告排序維持前位 | 檢視真值候選在評分排序中的位次變化 |
