# 剪輯轉檔接縫黑畫面成因分析與多輸入無縫輸出方案

本文件彙整關於「轉檔後影片在廣告銜接處出現瞬間黑畫面」的深度技術分析、電視端與電腦端播放差異的根本原因，以及兼顧「電視零黑屏」與「100% 影格完整度」的建議改進方案。

---

## 一、 問題現象與背景

在對含有中插廣告的電視串流錄製影片（如 `S02-07.mp4`）進行廣告偵測與移除後：
1. **輸出檔案完整性**：廣告圖卡已成功移除，且總時長與總影格數經安全閘門（Safety Gate）嚴格驗收合格。
2. **播放表現差異**：
   - **電腦本機播放器**（如 PotPlayer、VLC、Windows Media Player）：播放至廣告剪除的銜接處時，畫面完全順暢、無任何異常黑屏。
   - **電視端 App 透過 NAS 串流播放**（如 Apple TV / Android TV / 智慧電視內建播放器）：在廣告被剪除的銜接處，會瞬間閃過約 2~3 格（約 50~100 毫秒）的黑畫面。
3. **排除原始轉場干擾**：
   透過介面的「4 格微調面板」逐幀檢查原始檔案，確認正片在廣告前後均為正常連續畫面，並無電視節目傳統的「進廣告淡出黑畫面（Fade to Black）」或「廣告後淡入黑畫面（Fade in from Black）」。

## 二、 深度底層探測與連環因果鏈分析

### 1. 實體檔案檢驗：MP4 內部「完全沒有黑影格」
使用 FFmpeg 的高靈敏度黑畫面探測濾鏡（`blackdetect=d=0.04:pic_th=0.98:pix_th=0.10`）對轉檔完成的正式輸出影片進行逐幀掃描：
- 探測結果顯示：在第 1 個接縫處（約 302.08 秒）與第 2 個接縫處（約 1981.76 秒），**沒有檢測到任何黑畫面序列（0 black frames）**。
- 逐格抽取的 PNG 圖片像素平均亮度（Mean Brightness）均在 100~120 之間，證實**檔案實體內部每一格都是真實的正片畫面，並無實體黑底影格**。

### 2. 根本起因：終端機警告背後的「異質解析度」地雷
在轉檔過程中，終端機曾出現以下警告訊息：
```text
輸出檔未通過品質驗收：實際 1654.6530s / 預期 2597.9635s（差 -943310.5 ms，容許 ±62.6 ms）；實際 39672 / 預期 62289；音訊 2597.9668s vs 視訊 1654.6530s（差 +943313.8 ms）
單一管線輸出未達品質標準，偵測到可能受廣告動態解析度改變或濾鏡重設干擾，自動切換至『分段隔離導出機制』進行修復...
```
- **核心真相**：原始片源的正片為特殊寬螢幕比例（**`1080x606`**，SAR 404:405），而電視台插播的商業廣告為標準 **`1920x1080`**（SAR 1:1）。
- 當使用單一連續解碼管線時，解碼器一路往下讀，撞上廣告的 1920x1080 時觸發了 H.264 SPS 動態改變，導致 FFmpeg 底層執行 **Filtergraph Re-initialization（濾鏡重新初始化）**，影格計數器被重置為 0，致使後段正片被徹底丟棄（少掉 15 分鐘）。
- 系統的安全防線（Safety Gate）攔截下這個瑕疵半成品，並**自動切換為「分段隔離導出機制」**：將各正片區間各自獨立轉碼，再透過 `concat demuxer`（`-f concat -c copy`）做無損拼接，順利 100% 救回整支影片的完整畫面。

### 3. 電視端閃黑的直接原因：電視晶片的硬體解碼保護（DPB Flush）
- **電腦端為什麼正常？**  
  電腦 CPU/GPU 運算強大、記憶體充足，播放器在遇上拼接容器時，能在 1~2 毫秒內平滑切換。
- **電視端為什麼閃黑？**  
  電視機或電視盒的晶片（SoC，如聯發科 MediaTek、Realtek、Amlogic 等）硬體規格極度保守，其專用解碼晶片（VPU）記憶體快取非常小。
  當播放器透過 NAS 讀取到銜接點時，串流中迎來了**全新宣告的 `IDR-Frame`（關鍵影格）與 `SPS/PPS` 規格參數**。電視晶片為了防止跨段落的參考影格污染而造成破圖或綠屏，硬體層會強制執行一次 **DPB Flush（清空解碼緩衝區）**。
  在清空到重新填入新畫面的短暫 50~100 毫秒內，視訊渲染器無畫面可交，底層預設顯示**純黑底色**，因而形成了肉眼所見的「瞬間黑畫面」。

## 三、 歷史版本（Commit `7226f41`）與現行架構對比

| 比較維度 | 舊版架構（Commit `7226f41`） | 現行架構（雙層防護機制） |
| :--- | :--- | :--- |
| **轉檔指令型態** | 純單一命令列：`split` $\rightarrow$ `trim` $\rightarrow$ `concat 濾鏡` | 優先單一管線，未達標自動啟用分段隔離 + `concat demuxer` |

| **電視播放表現** | ✅ **完全無黑屏**，無縫平滑滑過 | ⚠️ 電視硬解因 DPB Flush 閃過 2~3 格黑畫面 |
| **容錯與品質驗收** | ❌ 無驗收閘門，遇異質解析度直接壞檔（缺 15 分鐘）且覆蓋原檔 | ✅ 具備強制驗收閘門，100% 保證影格數、時長與影音同步精確 |

## 四、 建議解決方案：同 Filtergraph 內多輸入連續管線（Multi-Input In-Memory Concat）

若要徹底消除電視端硬解觸發的黑畫面，終極關鍵在於：
**「在輸出端維持全程單一連續編碼（連貫 GOP、全域單一 SPS/PPS，無容器拼接縫），同時在輸入端隔離廣告的 1920x1080 地雷。」**

### 架構原理
不要讓單一解碼器順著時間軸跨越正片與廣告的邊界，而是**替每一個保留的正片區間指派專屬的輸入端（Input）**，並在進入濾鏡時施加尺寸標準化（Scale Lock），最後在記憶體內部直接咬合後送交單一編碼器：

```text
[Input 0: 正片段 1 (0 ~ 302s)]    ──> [scale=1080:606] ──> [v0] ┐
[Input 1: 正片段 2 (327 ~ 2007s)] ──> [scale=1080:606] ──> [v1] ┼──> [concat=n=3:v=1:a=1] ──> [單一 QSV 編碼器] ──> output.mp4
[Input 2: 正片段 3 (2033 ~ 2486s)]──> [scale=1080:606] ──> [v2] ┘
```

### 命令列設計範例
```bash
ffmpeg -hide_banner -nostdin -y -v warning \
  -ss 0.000000 -t 302.080000 -i S02-07.mp4 \
  -ss 327.903000 -t 1679.680000 -i S02-07.mp4 \
  -ss 2033.343000 -t 453.240000 -i S02-07.mp4 \
  -filter_complex \
  "[0:v]scale=1080:606,setsar=404/405[v0]; \
   [1:v]scale=1080:606,setsar=404/405[v1]; \
   [2:v]scale=1080:606,setsar=404/405[v2]; \
   [v0][0:a][v1][1:a][v2][2:a]concat=n=3:v=1:a=1[vout][aout]" \
  -map "[vout]" -map "[aout]" \
  -c:v h264_qsv -global_quality 24 -preset fast \
  -c:a aac -b:a 128k \
  -movflags +faststart \
  output.mp4
```

### 方案優勢
1. **徹底消滅電視播放黑畫面**：
   `output.mp4` 全程由同一個硬體編碼器自始至終連續編碼生成，**沒有段落拼接點、沒有額外插入的 IDR 重設**。電視晶片視其為天然無縫長片，解碼緩衝區不會 Flush，接縫完全無黑屏。
2. **完全免疫動態解析度改變**：
   每個 input 只在自己的正片時間範圍內解碼，解碼器**在輸入階段就完全不接觸廣告片段**，永遠不會收到 1920x1080 的資料流，濾鏡管線永遠不重設。
3. **前置尺寸鎖定（Scale & SAR Lock）**：
   即使 demuxer seek 在邊界有些微預讀，前置的 `scale=1080:606,setsar=404/405` 也會強制將所有畫面標準化，確保進到 `concat` 濾鏡的每一幀都是純淨統一的格式。
4. **零磁碟暫存檔，效能最佳**：
   不需要在硬碟上寫入多個分段 `.mp4` 暫存檔，省去多次磁碟寫入與讀取，全程在記憶體管線完成，轉碼耗時更短。

## 五、 結論與建議

- **目前的輸出檔案是健康的**：實體影格 100% 完整、無遺失、影音同步精度在毫秒級，電視端的短暫黑畫面屬於硬體解碼保護的顯示現象。
- **後續架構升級建議**：若希望追求極致的觀影無縫體驗，可將轉檔管線實作演進為**「同 Filtergraph 內多輸入連續管線（Multi-Input In-Memory Concat）」**，便能同時達成「舊版的極致無縫連貫」與「新版的絕對完整可靠」。
